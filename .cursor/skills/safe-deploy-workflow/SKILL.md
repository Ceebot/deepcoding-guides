# Safe Deploy Workflow

Цель: показать, как агент может выполнить рутинный деплой по регламенту, но не получить право
самовольно менять сервер.

## Главные правила

1. Сначала только чтение: структура каталогов, версии Docker, свободные порты, состояние сервисов.
2. Эталонный сервер всегда read-only.
3. Перед любым изменением агент показывает план и спрашивает разрешение.
4. Секреты не писать в файлы, коммиты и сообщения.
5. Длинные удаленные команды оформлять скриптом, загружать на сервер и запускать файл.

## Что собрать до старта

- Целевой сервер: host, user, способ доступа.
- Эталонный сервер: где уже работает похожий проект.
- Домены и статус DNS.
- Репозитории и нужные ветки.
- Список модулей и порядок запуска.
- Что считаем успешным деплоем.

## Фаза 1. Разведка

На целевом сервере:

```bash
cat /etc/os-release
docker --version
docker ps
df -h /
free -h
ss -tlnp
```

На эталоне:

```bash
docker stack ls
docker service ls
ls -la ~/project
```

После разведки агент коротко докладывает:

- что уже установлено;
- какие порты заняты;
- какие конфиги нужны с эталона;
- какие действия будут изменять сервер.

## Фаза 2. Разрешение

Перед изменениями агент обязан спросить:

```md
Я закончил read-only проверку.
План изменений:
1. ...
2. ...
3. ...

Можно приступать к изменениям на целевом сервере?
```

Без явного ответа "да" изменения запрещены.

## Фаза 3. Деплой

Общий порядок:

1. Подготовить системного пользователя и Docker.
2. Склонировать репозитории.
3. Сверить ветки с эталоном.
4. Скопировать production-конфиги с эталона без секретов.
5. Подставить домены целевого окружения.
6. Создать БД и volume.
7. Собрать образы.
8. Запустить сервисы.
9. Выполнить миграции и seed/fixtures, если они нужны.

## Фаза 4. Проверка

```bash
curl -I https://example.test
docker service ls
docker ps
docker logs --tail=100 service_name
```

Успех:

- все сервисы подняты;
- HTTPS отвечает;
- миграции прошли;
- smoke-test приложения проходит;
- в логах нет повторяющихся ошибок.

## Отчет

В финале агент пишет коротко:

| Модуль | URL | Статус | Ветка | Комментарий |
|--------|-----|--------|-------|-------------|
| auth | https://auth.example.test | ok | main | HTTPS работает |

Также указывает, что не было сделано: например, не загружены тестовые данные или не подключен cron.
