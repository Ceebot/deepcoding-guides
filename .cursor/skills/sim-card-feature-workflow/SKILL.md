# SIM Card Feature Workflow

Цель: не начинать задачу с кода. Сначала понять ТЗ, найти похожие места и только потом менять проект.

## Когда применять

- новая фича в `project/`;
- изменение схемы БД;
- импорт данных;
- исправление поведения, описанного в ТЗ;
- обновление seed-данных.

## Обязательный порядок

1. Прочитать `project/telecom-sim-cards-spec.md`.
2. Прочитать свежие записи `task_logs.md`.
3. Найти похожие места в `project/`: миграции, seed, Makefile, SQL-запросы.
4. Сформулировать короткий план.
5. Сделать минимальный diff. Новую SQL-проверку начинать с шаблона `assets/business-check.sql`.
6. Запустить проверки: `bash scripts/run-checks.sh`.
7. Обновить `task_logs.md`.

## Правила реализации

- Все изменения тестового проекта делать только внутри `project/`.
- Не менять ТЗ под код. Код должен следовать ТЗ.
- Миграции должны быть идемпотентными для учебного запуска.
- Seed-данные должны проходить после `make db-clean`.
- Если меняется структура данных, проверить связанные CHECK-ограничения.
- Стиль бизнес-SQL-проверок — см. `references/sql-conventions.md` (читать по надобности).

## Бандл скилла

- `scripts/run-checks.sh` — пересборка БД и smoke-проверка (исполняемый код, агент его запускает).
- `references/sql-conventions.md` — соглашения по SQL, подтягивать только когда пишешь запрос.
- `assets/business-check.sql` — шаблон-заготовка новой проверки.

## Формат результата

В финале агент пишет:

- что изменено;
- какие проверки запускались;
- что добавлено в `task_logs.md`;
- какие ограничения остались.
