# Этап 8. Тесты, ревью и контроль качества

[← К roadmap](../README.md)

Цель: не верить ИИ на слово и принимать только проверенный код.

Код от агента считается "грязным", пока не прошел проверки. ИИ может придумать несуществующий метод, сломать краевой случай или написать небезопасное решение. Поэтому после реализации включается Zero Trust: тесты, линтеры, ревью и аудит.

## Контрольный выход

После AI-правок нужно проверять:

- Tests: unit, integration, e2e.
- Lint / format.
- Typecheck.
- Static analysis.
- Security scan.
- Manual QA.
- Code review.
- Cross-agent review: другой агент проверяет решение.

## Собственные субагенты в Cursor

Для повторяемых проверок можно создать своего субагента командой:

```md
/create-subagent
```

В промпте опишите имя, роль, контекст проекта, ограничения и задачи агента. Например: `tester` пишет тесты и ищет краевые случаи, а `reviewer` проверяет архитектуру, безопасность и производительность.

Вызывать такого агента можно через слэш-команду в чате Cursor:

```md
/tester Проверь текущие изменения и добавь недостающие тесты. Production-код не меняй.
/reviewer Проведи ревью текущего diff. Ищи баги, уязвимости и пропущенные проверки.
```

Используйте субагентов после реализации отдельного блока, перед merge/commit или когда нужен свежий взгляд без контекста агента-разработчика.

## Агент-тестировщик

Отдельный агент смотрит на задачу свежим взглядом. Его цель - не писать бизнес-логику, а проверять ее.

```md
Действуй как строгий QA-инженер.
Твоя задача - сломать текущую реализацию тестами.
Не меняй production-код.
Покрой happy path, edge cases, null, неожиданные типы данных и ошибочные входные данные.
```

## Агент-ревьюер

```md
Проведи code review текущих изменений.
Ищи реальные баги, регрессии, проблемы безопасности, производительности и пропущенные тесты.
Не предлагай стилистический рефакторинг без причины.
Ответ: severity, файл, проблема, как исправить.
```

## Глубокий аудит

```md
Проведи аудит текущих изменений.
Проверь безопасность, производительность, работу с данными и соответствие документации.
Не добавляй новый функционал.
Дай только точечные проблемы и конкретные исправления.
```

## Домашнее задание

- Взять AI-сгенерированную правку.
- Запустить тесты и линтер.
- Попросить агента-тестировщика найти недостающие проверки.
- Попросить агента-ревьюера найти баги, уязвимости и узкие места.
- Исправить минимум одну найденную проблему.
