# Этап 5. Правила, инструкции и память проекта

[← К roadmap](../README.md)

Цель: сделать так, чтобы ИИ помнил правила проекта не из головы разработчика, а из файлов.

## Базовые файлы

- `AGENTS.md`/`CLAUDE.md`/`QWEN.md` - общие правила для AI-агентов.
- `.cursor/rules/*` - правила для Cursor.
- `task-logs.md` - короткая история важных изменений.

## Автоматические и подключаемые правила

Есть два типа правил:

- Основные правила проекта. Они автоматически подтягиваются в контекст каждого запроса. Обычно это `AGENTS.md`, `CLAUDE.md`, `QWEN.md` (в зависимости от используемого агента) и правила Cursor с режимом `always apply`.
- Подключаемые правила. Они подтягиваются только вручную, по содержанию промпта или для конкретных файлов. Так удобно хранить подробности по backend, frontend, тестам, миграциям, API и отдельным фичам.

В Cursor для `.cursor/rules/*.mdc` можно выбрать режим:

- `always apply` - правило всегда добавляется в контекст.
- `apply intelligently` - Cursor сам подключает правило, если его описание в description подходит по смыслу на текущую задачу.
- `apply to specific files` - правило работает только для выбранных файлов или [glob-паттернов](https://cursor.com/ru/docs/rules).
- `apply manually` - правило подключается только вручную, когда ты явно его упоминаешь.

Практичный подход: держать в always-правилах только короткие базовые ограничения, а длинные архитектурные инструкции выносить в подключаемые `.mdc`-файлы.

## Что можно писать в правилах

- Стек проекта.
- Команды: test, lint, build, typecheck.
- Стиль кода.
- Запреты: не трогать миграции без спроса, не менять публичный API, не добавлять зависимости без причины.
- Где искать документацию.
- Как делать ревью.
- Ссылки на файлы документации

## Пример `AGENTS.md`

```md
# AGENTS.md

## Commands

- `npm test` - run tests.
- `npm run lint` - run linter.
- `npm run build` - production build.

## Rules

- Prefer existing patterns.
- Do not add dependencies without approval.
- After code edits run relevant tests.
- Never commit secrets.

## Project Map

- `src/api` - backend routes.
- `src/domain` - business logic.
- `src/ui` - React components.
```

Пример `AGENTS.md` этого проекта: [AGENTS.md](../AGENTS.md)

## История изменений проекта `task-logs.md` и зачем он нужен

ИИ часто теряет историю длинной работы. Короткий лог помогает восстановить контекст:

```md
# task-logs.md

2026-05-03
- Added CSV export for orders.
- Tests: `npm test -- orders`.
- Risk: timezone formatting still needs manual check.
```

Для автоматического добавления `task-logs.md` в контекст можно явно об этом попросить в `AGENTS.md` либо других файлах документации (пример: [AGENTS.md](../AGENTS.md))

Пример `task-logs.md` этого проекта: [task_logs.md](../task_logs.md)

## Проблема раздутого `task-logs.md`

Со временем `task-logs.md` увеличивается в размерах и заполняет контекст лишними данными, которые не относятся к текущей задаче. Больше 350 строк - это уже много. Решение:

- Периодически вручную удалять старые записи из `task-logs.md` изменений совсем старых дат, которые уже не актуальны.
- Периодически просить ИИ значительно сократить логи в `task-logs.md`, при этом сохранив суть изменений.

Данную процедуру можно автоматизировать, указав об этом явно в `AGENTS.md` либо других файлах документации. Так же можно написать скилл (о скиллах в следующих этапах)
