# Этап 9. Работа с файлами и разными форматами данных

[← К roadmap](../README.md)

Цель: использовать ИИ не только для кода, но и для любых входящих данных — требований, таблиц, спецификаций, логов и скриншотов.

## ИИ — универсальный приёмник данных

В реальной работе мы взаимодействуем не только с кодом. От бизнеса и смежных команд приходят PDF и Word с требованиями и ТЗ, Excel и CSV с данными, спецификации API, простыни логов, скриншоты ошибок. Всё это можно и нужно отдавать ИИ, чтобы ускорять работу.

Что можно скармливать:

- скриншоты ошибок и упавшего UI;
- макеты интерфейсов;
- PDF с требованиями и спецификациями API;
- DOCX с ТЗ;
- Excel/CSV с данными;
- логи;
- SQL-дампы без секретов;
- любые изображения для visual debug.

## Документация как код

Не храните входящие файлы на рабочем столе. Складывайте их в репозиторий и версионируйте в Git — тогда ИИ берёт контекст напрямую из проекта и строит код на реальных, версионируемых требованиях. В учебном проекте для этого есть папка `project/files/` (тарифы, требования, спеки API, выгрузки клиентов, статьи, скриншоты, логи).

## Markdown — самый «читаемый» формат

Нативный формат для ИИ — Markdown (`.md`). Можно просить ИИ конвертировать тяжёлый Word в md и красиво хранить в проекте, но это не обязательно: современные модели хорошо парсят исходники как есть.

## ИИ умеет запускать код для разбора файлов

Если формат сложный или данных много, агент сам пишет скрипт-парсер (например, на Python через `openpyxl`), выполняет его и возвращает готовую выжимку или сразу — SQL и данные. Так устроены Advanced Data Analysis у OpenAI и Computer Use у Anthropic.

## Зрение ИИ

ИИ принимает картинки. Скриншот ошибки запроса к БД или упавшего экрана → модель прочитает текст с картинки, поймёт контекст и подскажет решение. Перепечатывать логи вручную больше не нужно.

## Главный приём: сначала разбор, потом генерация

Не просите сразу «сделай». Просите ИИ **сначала показать понимание** — как он сопоставил данные, какие строки спорные, какой план изменений — и только после вашего «ОК» генерировать код или данные. Так вы остаётесь в контроле и не доверяете выводу слепо.

## Примеры на учебном проекте

Все файлы лежат в `project/files/`. Под каждый — короткий промпт.

### Excel → данные в БД

```md
В project/files/tariffs/услуги-тарифы-2026.xlsx — прайс услуг от отдела тарифов.
Прочитай его (напиши и выполни Python-скрипт через openpyxl).
Сначала покажи, как ты сопоставил колонки Excel с полями таблицы services,
и какие строки вызывают вопросы.
После моего ОК — сгенерируй seed с INSERT-ами в services.
```

ИИ сам напишет парсер, отбросит «грязные» строки (пустой тип, отрицательная цена, неизвестный статус) и смаплит русские значения в значения схемы.

### Word с требованием → изменение схемы

```md
В project/files/requirements/change-request-esim.docx — новое требование от бизнеса.
Прочитай его и сформулируй, какие изменения в схеме нужны.
Покажи план изменений и влияние на существующие таблицы и ограничения.
После согласования — напиши следующую миграцию (без потери данных).
```

Хороший агент не лепит вслепую — он замечает ограничения СУБД (например, что в SQLite нельзя расширить CHECK обычным `ALTER`) и предлагает безопасное решение. Вы проверяете и применяете.

### PDF со спецификацией API → сверка модели данных

```md
В project/files/api/payment-gateway-api.pdf — спецификация API платёжного шлюза.
Извлеки допустимые способы оплаты и статусы платежей.
Сравни с CHECK-ограничениями нашей таблицы payments и укажи расхождения.
Пока ничего не меняй — только предложи.
```

### CSV → очистка и загрузка

```md
В project/files/clients/импорт-юрлиц.csv — выгрузка корпоративных клиентов.
Сначала опиши правила проверки качества: дубли по ИНН, формат телефона и email.
Покажи проблемные строки.
После моего ОК — сгенерируй чистые INSERT-ы.
```

### Скриншот / лог → поиск причины

```md
На скрине project/files/screenshots/ошибка-fk-constraint.png — ошибка при заполнении БД.
Объясни причину и укажи, в каком запросе и порядке вставки проблема. Предложи фикс.
```

```md
В project/files/logs/seed-import.log — лог упавшего импорта.
Найди первую реальную причину падения (не следствие), процитируй строку и предложи фикс.
```

## Структура vs данные

Полезное разграничение, которое всплывает на таких задачах:

- **изменения структуры** (таблицы, индексы, новые поля и статусы) → миграции;
- **данные** (справочники, клиенты, статьи) → сиды.

ИИ помогает с обоими: из Word-требования рождается миграция, из Excel/CSV/Word — сид.

## Домашнее задание

- Возьмите реальный файл: скриншот ошибки, CSV или PDF с требованиями.
- Попросите ИИ **сначала описать наблюдения** — что увидел, какие проблемы, какой план.
- Только потом попросите сгенерировать исправление, проверку или код.
- Сложите файл в репозиторий, чтобы он остался в контексте проекта.
