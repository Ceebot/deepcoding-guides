# Этап 3. Базовая работа с ИИ

[← К roadmap](../README.md)

Цель: научиться ставить задачи так, чтобы ИИ делал полезную работу, а не угадывал.

## Из чего состоит хороший prompt

- Роль: кем должен быть ИИ.
- Контекст: проект, стек, файлы, ограничения.
- Задача: что сделать.
- Формат результата: план, diff, список рисков, тесты.
- Критерий готовности: как понять, что задача выполнена.

## Шаблон

```md
Ты senior backend-разработчик.
Проект: Rails API.
Задача: добавить endpoint для экспорта заказов в CSV.
Сначала изучи текущие routes/controllers/services.
Не меняй код до плана.
После реализации запусти тесты и покажи риски.
```

Для того, чтобы не повторять ИИ его роль и базовое описание проекта, существуют пользовательские и проектные правила, о них будет рассказано в следующих этапах.

## Полезные режимы общения

- "Сначала задай вопросы" - когда задача мутная.
- "Сначала найди похожие места в проекте" - когда важно попасть в стиль. (ИИ-агенты очень хорошо справляются с задачами по аналогии с уже решенными)
- "Сделай минимальное изменение" - когда нельзя раздувать код.
- "Покажи риски" - когда решение влияет на пользователей.
- "Проверь себя" - когда нужна самопроверка перед ответом.

## Домашнее задание

- Составить 5 prompts: для объяснения кода, реализации, тестов, ревью, debug.
- Один prompt прогнать на реальном проекте.
- Зафиксировать, что пришлось уточнять после первого ответа.
