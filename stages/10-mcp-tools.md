# Этап 10. MCP и внешние инструменты

[← К roadmap](../README.md)

Цель: подключить ИИ к реальным источникам данных и инструментам, чтобы агент перестал работать «по памяти» и начал проверять.

## Зачем это нужно

Обычный ИИ без инструментов знает только то, что выучил при обучении, плюс то, что вы вручную вставили в чат. Отсюда две беды:

- **Устаревшие знания** — у модели есть «дата обучения», и она советует версию библиотеки, которой уже два года.
- **Галлюцинации** — модель уверенно выдумывает несуществующий метод, потому что «по логике он должен быть».

MCP даёт агенту руки и глаза: доступ к свежей документации, к браузеру, к быстрому поиску по проекту, к базе, к логам. Агент перестаёт угадывать и начинает смотреть в реальный источник.

## Что такое MCP

MCP (Model Context Protocol) — это стандартный способ подключать к агенту инструменты. Аналогия — USB-C: единый разъём вместо костыля под каждый инструмент.

Главное: это **стандарт, а не фишка одного редактора**. Один и тот же MCP-сервер работает в Cursor, Claude Code, Codex, opencode и других инструментах. Настроили один раз — понимаете везде. Дальше примеры показаны на Cursor, но принцип одинаковый.

## Два типа внешних инструментов

Не путайте два разных понятия:

- **MCP-серверы** — подключение агента к внешним системам и данным (свежая дока, браузер, поиск по проекту, база, GitHub). Дают доступ туда, куда модель сама не дотянется.
- **Плагины и скиллы** — не новые данные, а готовые рабочие процессы и экспертиза (как набор регламентов и чек-листов). Пример — `superpowers`.

MCP — это ключи и пропуска к системам. Плагины — инструкции «как правильно делать работу».

## Как подключить MCP

Три способа, от простого к ручному:

1. **Каталог [cursor.directory](https://cursor.directory/)** — витрина готовых инструментов. Находите нужный MCP и жмёте «Add to Cursor», конфиг прописывается сам. Минус: в каталоге есть не всё.
2. **Через GitHub-репозиторий** — у каждого нормального MCP есть страница с инструкцией. Можно просто дать ссылку агенту в чат и попросить подключить — он сам прочитает README и настроит.
3. **Вручную через `mcp.json`** — когда хочется понимать, что именно прописывается. В Cursor: `Settings → MCP` или файл `.cursor/mcp.json`.

```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp"]
    }
  }
}
```

После подключения в списке MCP загорается зелёный кружок. Если вместо него ошибка — откройте логи в Cursor, скопируйте, вставьте в чат и попросите агента починить (обычно это не та версия Node, не установлен пакет или опечатка в конфиге):

```md
MCP-сервер [имя] подключается с ошибкой. Вот логи:
[вставить логи]
Разберись в причине и исправь конфигурацию.
```

## Полезные инструменты на практике

### Context7 — свежая документация

Подтягивает актуальную документацию по конкретной версии библиотеки прямо в контекст. Не из памяти модели, а из реального источника. Витрина с поддерживаемыми библиотеками: [context7.com](https://context7.com/). Репозиторий: [github.com/upstash/context7](https://github.com/upstash/context7).

Приём: один и тот же вопрос с инструментом и без — разница в надёжности ответа.

```md
Используй Context7: возьми актуальную документацию openpyxl
и покажи короткий пример, как прочитать значения ячеек из Excel-файла.
```

### Playwright — настоящий браузер

Даёт агенту глаза: он сам открывает страницу, кликает, читает консоль, делает скриншот. Замыкает цикл — написал UI → открыл → увидел ошибку → починил → проверил. Репозиторий: [github.com/microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp).

```md
Через Playwright открой https://playwright.dev.
Найди раздел про установку, сделай скриншот и процитируй команду.
Если в консоли есть ошибки — покажи их.
```

В Cursor есть и встроенный браузер — вызывается через `@browser`, работает похоже. Отдельный Playwright MCP мощнее по управлению и не привязан к одному редактору.

### fff — быстрый поиск по проекту

Файловый поиск с ранжированием по релевантности: недавно изменённые и git-dirty файлы всплывают первыми. Агент быстрее и точнее собирает контекст, меньше «пылесосит» лишнее — экономия времени и токенов. Репозиторий: [github.com/dmtrKovalenko/fff](https://github.com/dmtrKovalenko/fff).

Чтобы не просить вручную в каждом промпте — пропишите один раз в глобальном правиле пользователя (см. [этап 5](05-rules-and-memory.md)):

```md
- For any file search or grep in the current git-indexed directory, use fff tools MCP.
```

### superpowers — готовые навыки агента

Это не MCP, а плагин со скиллами: библиотека рабочих процессов от опытных инженеров (брейншторм требований, системная отладка, TDD, ревью). Агент сам подключает нужный навык под задачу. Ставится как плагин через маркетплейс, нативно живёт в Claude Code; в Cursor роль «готовых процессов» играют свои правила и команды.

## Когда использовать MCP

- Нужна актуальная документация по библиотеке.
- Нужно протестировать UI в браузере.
- Нужно посмотреть ошибку в логах или в Sentry.
- Нужно прочитать issue или PR на GitHub.
- Нужно дёрнуть API (Postman) или запрос к dev/stage-базе.

## Контроль и безопасность

В духе deepcoding — инструменты дают силу, и её надо контролировать:

- **Не вешайте десять MCP «на всякий случай».** Каждый кушает контекст и токены, а лишние ещё и путают агента — он лезет в браузер там, где хватило бы поиска. Включайте только нужное под задачу.
- **Следите за доступами.** MCP к базе или боевым системам — это реальные ключи в руках агента. Никакого production и секретов без явной необходимости, для базы — только dev/stage. Zero Trust с [этапа 8](08-quality-control.md) никуда не делся: инструмент расширяет руки агента, но за руль держитесь вы.

## Пример

```md
Используй документацию React Query через Context7.
Проверь, как правильно инвалидировать query после mutation.
Потом предложи правку в нашем коде.
```
