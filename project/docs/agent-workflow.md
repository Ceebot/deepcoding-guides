# Workflow агентов

Учебный проект развивается цепочкой субагентов (см. `.cursor/skills/subagent-workflow/`).

## Роли

| Агент | Задача |
|-------|--------|
| **planner** | план в `.cursor/plans/`, сверка с ТЗ |
| **worker** | реализация в `project/`, тесты, `make db-reset` / `make test` |
| **tester** | прогон проверок, регрессии |
| **reviewer** | ревью схемы, SQL, скриптов |

## Порядок

1. Постановка задачи → planner читает `telecom-sim-cards-spec.md` и `todo.md`.
2. План → worker выполняет шаги строго в `project/`.
3. Worker запускает `make db-reset`, `make db-audit` (если есть), `make test`.
4. Tester подтверждает зелёные проверки.
5. Reviewer — финальный аудит.

## Журнал

После любых правок внутри `project/` worker добавляет короткий пункт в `task_logs.md` (корень репозитория) по skill `update-task-log`. Без длинных списков файлов.

## Ограничения

- Схема и миграции — осознанные изменения, не «для теста».
- Демо-данные вымышленные; паспорта и реквизиты не реальные.
