# Тарифы и помесячные начисления — спецификация

## Цель

Добавить в учебный проект отдельную модель тарифов, назначение текущего тарифа SIM-карте, повторяемое начисление ежемесячной абонплаты и отчёт по начисленной выручке.

Модель остаётся намеренно простой: история смен тарифов отдельно не хранится. Прошлые начисления объясняются неизменяемыми снимками в `charges`.

## Область работ

- таблицы `tariffs`, `tariff_services`, `charges`;
- nullable-ссылка `sim_cards.tariff_id`;
- триггеры назначения тарифа и неизменяемости начислений;
- миграция схемы и обратная миграция;
- тарифы, связи, назначения и начисления в seed-данных;
- команда `charge --month YYYY-MM` и цель `make db-charge`;
- проверка активных SIM-карт без тарифа в `queries/integrity/`;
- отчёт по начисленной выручке в `queries/reports/`;
- тесты и обновление документации проекта.

## Модель данных

### `tariffs`

Тариф хранит коммерческое предложение целиком:

- `id` — первичный ключ;
- `name` — уникальное обязательное имя;
- `description` — обязательное описание;
- `monthly_fee NUMERIC NOT NULL CHECK (monthly_fee >= 0)` — полная ежемесячная абонплата;
- `status` — `active` или `archived`, по умолчанию `active`;
- `created_at` — время создания, по умолчанию `datetime('now')`.

Нулевая абонплата допустима для учебного бесплатного тарифа. Архивирование не меняет уже назначенные карты и прошлые начисления.

### `tariff_services`

Таблица описывает состав тарифа:

- `tariff_id` → `tariffs.id`;
- `service_id` → `services.id`;
- составной первичный ключ `(tariff_id, service_id)`.

Дополнительные объёмы и цены услуг здесь не хранятся. Стоимость тарифа задаётся одним полем `tariffs.monthly_fee`.

При удалении тарифа его связи с услугами удаляются каскадно. Удаление услуги, включённой в тариф, запрещается через `ON DELETE RESTRICT`.

### `sim_cards.tariff_id`

В `sim_cards` добавляется nullable-поле `tariff_id` со ссылкой на `tariffs.id`.

Отсутствие тарифа допустимо на уровне схемы для SIM-карты в любом статусе. Активную SIM без тарифа выявляет отдельный бизнес-аудит, а не `NOT NULL` или другой жёсткий constraint. Это соответствует существующему подходу `clients-without-type-details`.

При удалении неиспользованного тарифа ссылка на SIM-карте сбрасывается через `ON DELETE SET NULL`. Если по тарифу уже есть начисления, удалить его не позволит `charges.tariff_id ON DELETE RESTRICT`.

### `charges`

Каждая строка — неизменяемый снимок ежемесячного начисления:

- `id` — первичный ключ;
- `sim_card_id` → `sim_cards.id ON DELETE RESTRICT`;
- `tariff_id` → `tariffs.id ON DELETE RESTRICT`;
- `billing_period` — календарный месяц строго в формате `YYYY-MM`;
- `tariff_name` — имя тарифа на момент начисления;
- `amount NUMERIC NOT NULL CHECK (amount >= 0)` — абонплата на момент начисления;
- `created_at` — время начисления, по умолчанию `datetime('now')`;
- `UNIQUE (sim_card_id, billing_period)`.

Формат периода проверяется `CHECK`: четыре цифры года, дефис и месяц от `01` до `12`.

Снимок защищается триггерами `BEFORE UPDATE` и `BEFORE DELETE`, которые завершают операцию через `RAISE(ABORT, ...)`. Изменение имени, цены или статуса тарифа не меняет существующие начисления. Финансовые записи не удаляются каскадно вместе с SIM-картой или тарифом.

## Ограничения назначения тарифа

Триггеры на `sim_cards` проверяют `tariff_id`:

- `BEFORE INSERT`, если `tariff_id` указан;
- `BEFORE UPDATE OF tariff_id`, если новое значение не `NULL`.

Назначить можно только тариф со статусом `active`. При попытке назначить архивный тариф операция завершается через `RAISE(ABORT, ...)`, в стиле `trg_payments_sim_card_client`.

Изменение статуса уже назначенного тарифа на `archived` разрешено. Карты сохраняют этот тариф и продолжают начисляться. Проверка выполняется только в момент назначения тарифа карте; отдельного триггера на `tariffs.status` нет.

## Помесячное начисление

CLI получает новую команду:

```bash
python scripts/manage_db.py --db <path> charge --month YYYY-MM
```

Для удобства `Makefile` предоставляет цель:

```bash
make db-charge MONTH=2026-02
```

Команда валидирует период и одной транзакцией выполняет `INSERT OR IGNORE INTO charges ... SELECT ...`.

В начисление попадают SIM-карты, которые:

- имеют `status = 'active'`;
- имеют ненулевой `tariff_id`;
- активированы раньше конца выбранного календарного месяца.

Статус тарифа в выборке намеренно не проверяется: ранее назначенный архивный тариф продолжает начисляться. Имя и сумма копируются из текущей строки `tariffs`.

Неполный месяц не пересчитывается пропорционально — создаётся полная абонплата. Повторный запуск за тот же месяц не создаёт дубль благодаря `UNIQUE (sim_card_id, billing_period)` и `INSERT OR IGNORE`.

Команда выводит период и количество созданных начислений. Некорректный `YYYY-MM`, отсутствующая схема или ошибка SQLite дают ненулевой код возврата.

Ограничение модели: без истории статусов SIM и назначений тарифов команда не предназначена для точного перерасчёта далёких прошлых периодов. Она использует текущее состояние карты и тарифа, сохраняя результат как снимок.

## Проверка целостности

Добавляется read-only запрос `queries/integrity/active-sim-cards-without-tariff.sql`.

Он возвращает SIM-карты со статусом `active` и `tariff_id IS NULL`. Чистые seed-данные должны давать ноль строк. Запрос автоматически включается в существующий `db-audit`, который читает все SQL-файлы каталога.

## Отчёт по выручке

Добавляется `queries/reports/revenue-by-tariffs.sql`.

Отчёт строится только по `charges` и показывает:

- `billing_period`;
- снимок `tariff_id`;
- снимок `tariff_name`;
- количество начислений;
- общую начисленную сумму.

Группировка выполняется по периоду, `tariff_id` и `tariff_name`, сортировка — по периоду и убыванию суммы. Это отчёт по начисленной абонплате, а не по фактически оплаченным платежам. Связь `charges` с `payments` в эту задачу не входит.

## Миграция и seed-данные

Новая миграция создаёт тарифные таблицы и `charges`, добавляет nullable-ссылку в `sim_cards`, индексы и триггеры. `schema.sql` синхронизируется с итоговым состоянием.

Обратная миграция удаляет новые объекты и возвращает `sim_cards` к прежней структуре. Из-за ограничений SQLite удаление `tariff_id` может потребовать безопасного пересоздания таблицы с восстановлением существующих индексов и триггеров.

Seed-данные:

- добавляют несколько активных и один архивный тариф;
- связывают тарифы с существующими услугами;
- назначают тарифы всем активным SIM-картам;
- оставляют часть неактивных SIM без тарифа;
- добавляют демонстрационные начисления минимум за один месяц;
- остаются повторяемыми через `INSERT OR IGNORE`.

## Тесты

Проверить:

- создание всех новых таблиц, колонок, индексов, внешних ключей и `CHECK`;
- nullable `sim_cards.tariff_id`;
- запрет назначения архивного тарифа при INSERT и UPDATE SIM-карты;
- возможность архивировать уже назначенный тариф;
- начисление по такому архивному тарифу;
- создание начислений только для подходящих активных SIM-карт;
- полную сумму для карты, активированной в середине месяца;
- отсутствие начисления до месяца активации;
- идемпотентность повторного запуска;
- снимок имени и суммы после последующего изменения тарифа;
- запрет UPDATE и DELETE строки `charges`;
- `ON DELETE RESTRICT` для SIM-карты и тарифа с начислениями;
- нулевой результат новой integrity-проверки на чистом seed;
- обнаружение активной SIM без тарифа;
- ожидаемую группировку отчёта по выручке;
- применение и откат новой миграции;
- повторяемость обновлённых seed-данных.

## Критерии приёмки

- `make db-reset`, `make db-check` и `make db-audit` проходят на чистой базе.
- `make db-charge MONTH=YYYY-MM` создаёт ожидаемые начисления и безопасно повторяется.
- Архивный тариф нельзя назначить заново, но уже назначенные карты продолжают начисляться.
- Начисления нельзя изменить или удалить обычными DML-операциями.
- Отчёт считает начисленную выручку из снимков `charges`.
- Полный набор тестов `make test` проходит.
